What you get

Antibody is software you run, not a website account. It sits next to your AI agent and holds the keys that let the agent read and write its memory on Walrus and Sui.

  • A command-line tool called antibody, for setup, payees and quarantines.
  • Four background processes started by antibody up: control, signer, Steward the agent, and the sentinel that watches the wallet.
  • A web console in your browser at http://127.0.0.1:7402. It only answers on your own computer.

There is no desktop app icon or app store app. You install it from a terminal, then use it in your browser.

How do I get Node.js 22?

The simplest way on macOS, Linux and WSL is nvm:

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
# open a new terminal, then:
nvm install 22
nvm alias default 22

Or download the LTS installer from nodejs.org.

I'm on Windows

Install the two prerequisites from PowerShell, then open a new window:

winget install --id Git.Git -e
winget install OpenJS.NodeJS.LTS

Use the PowerShell installer below. Git Bash works too. For live mainnet use with full key separation, WSL2 is better: Windows can't stop one Antibody process reading another's key file.

Install

It checks your system, downloads Antibody and adds the antibody command. Use the copy button rather than selecting the text.

Windows (PowerShell)

irm https://antibody-memory.netlify.app/install.ps1 | iex

macOS, Linux, or Git Bash on Windows

curl -fsSL https://antibody-memory.netlify.app/install.sh | bash

Then open a new terminal window (on macOS/Linux, if it printed a PATH line, run that first) and check it worked:

antibody --help
Install by hand instead 
git clone https://github.com/linoxbt/Antibody.git ~/.antibody-app
cd ~/.antibody-app
npm ci --omit=dev
mkdir -p ~/.local/bin
ln -sf ~/.antibody-app/bin/antibody.mjs ~/.local/bin/antibody

First run (simulated, no keys)

Antibody starts on a simulated chain, so you can try everything safely before touching mainnet. Output is labelled SIMULATED.

  1. Create keys and a practice account
    antibody setup
  2. Start Antibody. It prints your sign-in link.
    antibody up
  3. Give Steward a payee and a fact to remember
    antibody payee add --label landlord --address 0x7a11ce0000000000000000000000000000000000000000000000000000001a2d --coin USDC --cap 500 --confirm 001a2d
antibody statement "Rent is 450 USDC (coin type 0xdba34672e30cb065b1f93e3ab55318768fd6fef66c15942c9f7cb846e2f900e7::usdc::USDC), paid on the 1st to my landlord at 0x7a11ce0000000000000000000000000000000000000000000000000000001a2d."
  4. Attack it: a stranger sends a coin that tries to change the landlord
    antibody dev airdrop
  5. Ask Steward to pay. The model is fooled; Antibody blocks it.
    antibody steward "Pay this month's rent."

Open the console

antibody up prints a link like http://127.0.0.1:7402/login#token=…. Open it in your browser and you are in. Need it again later?

antibody login

On mainnet, you can also sign in with the wallet that owns your Antibody account: open http://127.0.0.1:7402 and choose your wallet.

Go live on mainnet

  1. Create your Walrus Memory account at memory.walrus.xyz with a wallet you control. That wallet is the owner. Copy the account ID (0x…).
  2. Get a mainnet API key at dashboard.tatum.io.
  3. Export the owner wallet's private key from your wallet's account settings (it starts with suiprivkey1). Antibody uses it only during setup, revoke and rotate. Use a dedicated owner wallet, not your main one.
  4. Put your settings in ~/.antibody/antibody.env (on Windows: %USERPROFILE%\.antibody\antibody.env, created with Notepad). Antibody reads this file on every command. 
    mkdir -p ~/.antibody && cat > ~/.antibody/antibody.env <<'EOF'
ANTIBODY_BACKEND=live
MEMWAL_ACCOUNT_ID=0xYOUR_ACCOUNT_ID
TATUM_API_KEY=YOUR_TATUM_KEY
OWNER_SUI_PRIVATE_KEY=suiprivkey1...
# Optional: a real model for Steward (any OpenAI-compatible API)
# LLM_BASE_URL=https://api.openai.com/v1
# LLM_API_KEY=sk-...
# LLM_MODEL=gpt-4o-mini
EOF
chmod 600 ~/.antibody/antibody.env
  5. Separate the keys. Live mode refuses to run if one role can read another's key. On a single-user machine, either give each role its own OS user, or accept the risk for testing: 
    sudo ANTIBODY_HOME=$HOME/.antibody ~/.antibody-app/scripts/setup-roles.sh   # proper isolation
# or, for a test machine only:
echo 'ANTIBODY_KEY_ISOLATION=simulated' >> ~/.antibody/antibody.env
  6. Register the four lane keys on-chain and write the ledger's first record:
    antibody setup
  7. Setup prints Steward's wallet address. Send it a little SUI for gas and the USDC it will pay with.
  8. Start it and sign in:
    antibody up

Optional: add ANTIBODY_CROSSCHECK_RPC_URL=https://fullnode.mainnet.sui.io:443 so a second provider must agree on your keys before any payment.

Everyday commands

antibody up / downStart or stop everything
antibody loginPrint a console sign-in link
antibody statusAccount, lane keys, wallet balances
antibody show --forensicWhat Steward can see, and what is excluded and why
antibody payee add|removeManage who Steward may pay
antibody quarantine --source 0x… --yesCut a poisoned source out of memory
antibody rebuild --freshRebuild from Walrus + Sui alone and compare

Logs live in ~/.antibody/logs/, one file per process.

On a phone

Antibody itself needs a computer: it runs background processes and holds keys. On a phone you can:

  • Use the sandbox. Open antibody-memory.netlify.app/login inside your wallet app's browser (in Slush: the Apps/browser tab) and connect. You get your own simulated Antibody.
  • Watch the demo in any mobile browser.
  • Reach your own install (advanced): the console only answers on the computer it runs on, by design. Use an SSH tunnel or a private network such as Tailscale, never a public port.

Update or remove

Update: stop Antibody, run the installer again, start it. Your keys and data in ~/.antibody are never touched.

Windows (PowerShell)

antibody down
irm https://antibody-memory.netlify.app/install.ps1 | iex
antibody up

macOS, Linux, Git Bash

antibody down
curl -fsSL https://antibody-memory.netlify.app/install.sh | bash
antibody up

Remove the program (keeps your keys and data):

antibody down
rm -rf ~/.antibody-app ~/.local/bin/antibody

On Windows (PowerShell):

antibody down
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\Antibody"

Deleting ~/.antibody also deletes your lane keys. Back up ~/.antibody/keys first, or revoke the keys on-chain.

Troubleshooting

Nothing matches. Check ~/.antibody/logs/, then open an issue with the message.

Installing

Node.js v18… is too old or Unknown file extension ".ts"

Antibody needs Node.js 22 or newer. Run nvm install 22 && nvm alias default 22, open a new terminal, and install again.

antibody: command not found

The command folder isn't on your PATH. Run the echo 'export PATH=…' line the installer printed, or add export PATH="$HOME/.local/bin:$PATH" to ~/.bashrc or ~/.zshrc. Then open a new terminal.

bash: $'\302\226curl': command not found (or '\342\200\213curl')

An invisible character came along when you copied the command, usually from selecting text in a chat app, PDF or document. Use the copy button on this page, or type the command by hand. On Windows, the PowerShell command avoids Git Bash altogether.

irm : The term 'irm' is not recognized / iex errors

You're in CMD or Git Bash, not PowerShell. Open Windows PowerShell from the Start menu and paste it there. In Git Bash, use the curl … | bash command instead.

running scripts is disabled on this system

PowerShell's execution policy blocks scripts. The irm … | iex command normally isn't affected; if it is, run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned once and try again.

'antibody' is not recognized as an internal or external command

Windows only updates PATH for new windows. Close PowerShell, open a new one, and try again. Still missing? The command is at %LOCALAPPDATA%\Antibody\bin\antibody.cmd.

winget : The term 'winget' is not recognized

Install App Installer from the Microsoft Store, or download Git from git-scm.com and Node.js from nodejs.org.

git is not installed

macOS: xcode-select --install. Ubuntu/Debian: sudo apt install -y git.

npm ERR! code EACCES or permission denied

Don't use sudo with npm. Install Node with nvm so it lives in your home folder, then run the installer again.

npm ci can only install packages when your package.json and package-lock.json are in sync

Your copy is half-updated. Run git -C ~/.antibody-app fetch origin main && git -C ~/.antibody-app reset --hard origin/main, then the installer again.

Could not download Antibody or network timeouts

Check that github.com and registry.npmjs.org are reachable. Behind a company proxy, set HTTPS_PROXY and npm config set proxy http://host:port.

~/.antibody-app exists but is not an Antibody install

Something else is in that folder. Move it away, or install elsewhere: ANTIBODY_APP_DIR=~/antibody-app bash install.sh.

Setup

refusing to overwrite existing key …

You already ran setup, and Antibody never overwrites keys. Keep going with antibody up. To truly start over, stop everything and move ~/.antibody aside (this abandons those keys).

ledger already has a genesis record / ledger is not empty

Setup already finished for this account. There's nothing to do; run antibody up.

set MEMWAL_ACCOUNT_ID to the account created on memory.walrus.xyz

Live mode needs your Walrus Memory account ID. Create the account at memory.walrus.xyz, then add MEMWAL_ACCOUNT_ID=0x… to ~/.antibody/antibody.env.

this step needs the owner wallet: set OWNER_SUI_PRIVATE_KEY

Setup, revoke and rotate are signed by the account owner. Add the owner's exported key (suiprivkey1…) to antibody.env. Use a dedicated owner wallet.

OWNER_SUI_PRIVATE_KEY controls 0xA…, but the account owner is 0xB…

The key belongs to a different wallet than the one that created the Walrus Memory account. Export the key of the wallet shown as owner.

ETooManyDelegateKeys (2)

The account already has the maximum of 20 delegate keys. Remove unused ones in the memory.walrus.xyz dashboard, then run setup again.

lane … key not visible on-chain yet

The transaction landed but the chain reader hasn't caught up. Wait 20 seconds and run antibody setup again. Keys already registered are reused.

ANTIBODY_BACKEND must be live or offline

Fix the spelling in antibody.env (or your shell). Leave it unset to stay on the simulated backend.

Starting

timed out waiting for …/control.sock (or signer.sock, agent.sock)

That process failed to start. Its reason is in ~/.antibody/logs/control.out (or signer.out, agent.out). The causes below are the usual ones.

listen EADDRINUSE: address already in use 127.0.0.1:7402

Antibody (or another program) already uses that port. Run antibody down first. To use another port, add ANTIBODY_WEB_PORT=7410 to antibody.env.

role control can read key files of user, agent, … run each role as its own OS user

Live mode enforces key separation. Run scripts/setup-roles.sh (see Go live). For a test machine only, add ANTIBODY_KEY_ISOLATION=simulated. On Windows, separation needs WSL2; native Windows runs with ANTIBODY_KEY_ISOLATION=simulated.

… .key must be mode 0600

A key file is readable by others. Fix it with chmod 600 ~/.antibody/keys/*/*.key.

no control key at …: run `antibody setup` first

Run antibody setup. If you moved ~/.antibody, set ANTIBODY_HOME to its new location.

timed out waiting for \\.\pipe\antibody-… (Windows)

A process didn't start. Read %USERPROFILE%\.antibody\logs\control.out (or signer.out, agent.out). If another Antibody is still running, run antibody down first.

listen EINVAL or ENAMETOOLONG on a .sock path

The folder path is too long for a socket (macOS allows about 100 characters). Use a shorter ANTIBODY_HOME, e.g. ~/.antibody.

this command runs as role "x" but ANTIBODY_ROLE=y

An ANTIBODY_ROLE variable is left over in your shell. Run unset ANTIBODY_ROLE; antibody up sets it per process.

Signing in

Every console page says 404 · No verified parent with no styling (Windows)

Fixed in the current version: older builds rejected Windows file paths. Update (see Update or remove), then open the new sign-in link that antibody up prints.

no operator token yet: start the console with antibody up

The console isn't running. Run antibody up, then antibody login.

operator link is invalid or from an earlier run

Links change every time Antibody restarts. Get a fresh one with antibody login.

this wallet is not the account owner (0x12ab…cd34)

Your wallet is on another account. Switch to the account shown in the message, or import the owner key into your wallet. The hosted sandbox accepts any wallet.

No Sui wallet found

Install Slush (or another Sui wallet) in this browser and reload. On a phone, open the page inside your wallet app's browser.

signature does not verify for this address

The wallet signed with a different account than it reported: pick the account again in the wallet. Accounts made with Google (zkLogin) are checked against the chain, so the node needs internet access to fullnode.mainnet.sui.io (or set ANTIBODY_ZKLOGIN_RPC_URL).

challenge expired or unknown; try again

You took longer than 5 minutes, or Antibody restarted. Click your wallet again.

too many failed sign-in attempts; wait a minute

Several failures in a row. Wait one minute, then try once with the right account.

Session ended. Sign in again.

Sessions last 12 hours, and restarting Antibody signs everyone out. Sign in again.

Payments and memory

BLOCK UNKNOWN_RECIPIENT

Steward tried to pay an address that isn't a signed payee. If it's legitimate, add it with antibody payee add. If not, Antibody just stopped an attack.

BLOCK LABEL_MISMATCH

Steward named a payee ("landlord") but used a different address than the one you signed. This is the classic memory-poisoning attack. Check Incidents and quarantine the source.

BLOCK OVER_CAP

The amount is above that payee's per-payment cap. If intended, remove and re-add the payee with a higher --cap.

BLOCK ASSET_MISMATCH or BAD_AMOUNT

Wrong coin for this payee, or an amount Antibody can't read. Say the coin and amount plainly, e.g. "Pay 450 USDC".

BLOCK SIMULATION_MISMATCH

The dry run did something other than the plain transfer, or needed too much gas. Check Steward's wallet has SUI for gas. Persistent? Treat it as suspicious.

BLOCK LEDGER_UNVERIFIED

Antibody can't prove its ledger is complete and untampered, so it pays nobody. Run antibody verify-ledger. If records are missing from the index, antibody restore-index.

BLOCK CHAIN_UNAVAILABLE

Chain reads failed, so Antibody fails closed. Check internet access and TATUM_API_KEY. With a second RPC set, "chain readers disagree on the delegate set" means the two providers report different keys: investigate before anything else.

payee changes need a typed confirmation: pass --confirm <last 6 characters>

A deliberate speed bump. Add --confirm with the last six characters of the address, e.g. --confirm 001a2d.

address must be a canonical Sui address (0x + 64 lowercase hex)

Use the full address, all lowercase. Names like SuiNS are never resolved, on purpose.

Steward says "I could not find a landlord address in memory"

Steward only uses what you told it. Add a fact with antibody statement "Rent is 450 USDC … to my landlord at 0x…".

ledger is at the MVP cap of 90 records

This version keeps at most 90 control records. Start a fresh account for now; larger ledgers come later.

Tatum Storage upload failed: HTTP 401/403

Incident reports need a mainnet Tatum key. Check TATUM_API_KEY. Without one, reports are saved locally and labelled simulated.

Hosted sandbox

the sandbox is full right now

The free sandbox has a limit on worlds. Try later, or install Antibody yourself.

slow down: too many actions this minute

Each sandbox allows about 40 actions a minute. Wait a moment.

My sandbox looks different from before

Sandboxes can be reset by you (Settings → Reset sandbox) or cleared during maintenance. They are simulated and hold nothing of value.
